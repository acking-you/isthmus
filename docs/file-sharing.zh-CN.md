# 文件互传

Isthmus 会找到同样运行着它的其他电脑，在对方电脑上点一下就配对，之后自动连上，把你拖到窗口里的文件发过去，并共享剪贴板。Mac 和 PC 用法一样：PC 上运行的是同一个应用的 Windows 版。代码在 `crates/isthmus-link`；每次改动都要遵守的规则见 [AGENTS.md](../AGENTS.md)。

## 怎么用

1. 两台电脑都打开 Isthmus。几秒内，各自的 **设备 › 附近** 里会出现对方。
2. 点对方旁边的 **配对**。对方的窗口会弹出来询问是否配对，两台电脑显示同样的 6 位数字；在那台电脑上点 **接受**。用 KVM 的话：点配对，切过去确认数字一致，点接受。（仍是 Isthmus 0.1 的电脑会改为显示一个配对码让你输入。）
3. 之后只要两台都开着，就会自动连上；已配对的设备显示 **已连接** 以及它走的路径。
4. 把文件或文件夹拖到窗口任意位置，它们会出现在 **待发送** 里；在要接收的设备旁点 **发送**。
5. 文件存到接收方的「下载」文件夹，保留原名（重名时为 `名称 (1).扩展名`）。**在访达中显示**（PC 上为 **在资源管理器中显示**）可以直接定位；页面顶部的文件夹按钮打开整个文件夹。

在一台电脑上复制文本，到另一台上粘贴：剪贴板会与所有已连接的已配对设备双向共享，每次同步都会提示（窗口在前台时是应用内提示，Isthmus 待在菜单栏或通知区域时是系统通知）。设备页上的 **共享剪贴板** 可以关闭它。仅限文本，最多 4 MB；密码管理器复制的内容（标记为隐藏或临时）不会离开它所在的电脑。macOS 15.4 及以后会在应用自行读取剪贴板前询问：在设备页点 **允许** 并允许粘贴，然后在「系统设置 › 隐私与安全性 › 从其他 App 粘贴」中把 Isthmus 设为 **始终允许**。在此之前，那台 Mac 上的复制不会发出，其他设备的复制仍会收到。

在设备的菜单里可以取消配对。两边都会忘掉这次配对；取消时对方若没开着，它回来时会被拒绝，并在那时忘掉自己这边。

## 路径：先走直连线，再走局域网

KVM 切换器只是在几台电脑之间切换同一套键盘、鼠标和显示器，它本身不会在两台电脑之间传数据。能传数据的是 **两台电脑之间直接相连的线**：插在 KVM 的 USB 口（或 Mac 上）的 USB 网卡，网线接到 PC 的网口；或者两台 Mac 之间的雷雳线。这样的线上没有路由器分配地址，两端会各自给自己分配一个 169.254/16 的地址（macOS 和 Windows 都会在一分钟内自动完成）。Isthmus 把 IPv4 地址全部是自分配地址的网卡视为 **直连线**，其余都视为 **局域网**。

| 路径 | 是什么 | 优先级 |
| --- | --- | --- |
| 直连线 | 只有 169.254 地址的网卡：两台电脑之间的一根线 | 第一 |
| 局域网 | 两台共同所在的 Wi-Fi 或有线网络 | 第二 |

- **连接。** 每次连接都按优先级依次尝试对方的地址，间隔四分之一秒，谁先连上用谁。直连线能通时大约一毫秒就连上，所以只要它通就一定选它；拔掉后，四分之一秒后局域网接手。
- **切回直连线。** 走局域网的会话每 15 秒检查一次直连线，一旦能通就切过去。
- **传输中断线。** 断掉的路径往往不会报错：Wi-Fi 掉线或拔掉网线后，TCP 会重传好几分钟系统才判定连接断开。所以发送方不等这个：一次写入 10 秒没有任何进展就结束本次尝试，下一次优先尝试其他路径。重试在四分之一秒后开始，间隔逐步增加到最多 3 秒，并在最后一次有数据流动后持续 2 分钟；每次都从接收方已有的字节处继续，所以传到一半拔掉网线，剩下的几秒内就改走 Wi-Fi。期间接收方会等待发送方回来。
- **说明原因。** 正在重试的传输会显示第几次重试、出了什么问题、在哪条路径上（「局域网 en1 上没有数据在流动」「直连线 en8 上的连接断开了」），下面附上系统自己的错误信息；失败的传输会保留最后一次的原因。

设备页会显示本机的每条路径（直连线或局域网、网卡、地址），每台已连接设备当前走的路径，以及每个传输走的路径。

## 安全

- **统一的握手。** 每个连接都是 TCP 加 Noise XX 握手（X25519、ChaCha20-Poly1305、BLAKE2s）。每台设备的长期密钥就是它的身份；设备 id 是密钥 SHA-256 的前 8 个字节。
- **发现只是发现，信任来自配对。** mDNS（`_isthmus._tcp`）只说明某个 id 在哪里、设备叫什么，不授予任何权限。只有配对时固定（pin）下来的密钥才让一台设备成为对端，之后的每次连接双方都必须证明自己持有该密钥。
- **配对。** 两台都是当前版本时：被添加的设备先承诺一个随机数（发送它的 SHA-256），另一台发送自己的随机数，前者再公开它的随机数，两台都显示由 Noise 握手哈希（覆盖双方密钥）和两个随机数算出的 6 位数字。中间人要跑两次握手，并且必须在得知诚实一方的随机数之前就定下自己在每一边的随机数，所以两边数字一致只能靠运气，概率百万分之一：接受前对一下数字就能发现它，和蓝牙的数字比较一样。不看就接受，相当于对当时的网络做一次信任。与版本 1 的设备配对时，则用用户输入的 6 位配对码跑 SPAKE2，中间人每次尝试只有一次猜测机会。被拒绝或失败的配对，双方都不会记录任何东西。
- **剪贴板** 只发给已配对的设备，走同样的加密会话，并且两端都开启共享时才会传。
- **收到什么。** 只有已配对的设备能发送，来自它们的文件会直接接收。传输清单里的每个路径都会在暂存文件夹下逐段重建：拒绝 `..`、绝对路径和空名称，并替换 Windows 无法保存的字符，因此不会有文件落到接收文件夹之外。所有文件都完整后才移动到位。
- **不出局域网。** 没有服务器，也没有中转。

## 权限与防火墙

- **macOS** 会询问一次 **本地网络** 权限（用于发现和连接另一台电脑），以及一次 **下载文件夹** 访问权限（文件存放处）；后者在首次启动时就会询问，确保你当时在 Mac 前。两个都请允许。如果开启了 macOS 防火墙，请允许 Isthmus 接受传入连接。
- **Windows** Defender 防火墙会在首次启动时询问。请同时允许 **专用和公用** 网络：一根直连线在 Windows 里是「未识别的网络」，会被归为公用网络。不允许的话 PC 仍能连到 Mac，但 Mac 可能找不到 PC。

Isthmus 监听 TCP 47821 端口（被占用时改用任意空闲端口），并使用 UDP 5353 端口的 mDNS。

## 文件

都在数据目录里（Mac 上是 `~/Library/Application Support/Isthmus`，Windows 上是 `%APPDATA%\Isthmus`），并遵守 [AGENTS.md](../AGENTS.md) 中的设置文件规则：之后的每个版本都能读取，未知字段会保留，原子写入。

| 文件 | 内容 |
| --- | --- |
| `link.json` | 设备名（`name`，未设置时为电脑名）、接收文件夹（`receiveDir`，未设置时为「下载」），以及是否共享剪贴板（`clipboard`，未设置时为开启） |
| `peers.json` | 每台已配对设备：id、固定的密钥、名称、系统，以及上次连上时的地址 |
| `link-identity.json` | 本机的密钥对，只有当前用户可读；删除它会让所有设备失去配对 |
| `link.lock` | 一台电脑上只有一个进程对外宣告本机；第二个应用副本会提示另一个 Isthmus 正在共享 |

彻底中断的传输会在接收文件夹里留下一个隐藏的 `.isthmus-<id>` 文件夹；三天没动过的会在下次启动时删除。

## 限制

- 两台电脑必须在同一个网络里，或用线直连。屏蔽组播的网络（部分访客 Wi-Fi）发现不了设备，不过已配对的设备仍会用上次连上的地址重新连接。
- 已配对设备发送文件无需确认；没有逐次的接收确认。
- 剪贴板只共享文本，不含图片和文件（文件请用「发送」）。
- 传输中每一帧都经过认证，但没有整个文件的哈希。发送过程中长度发生变化的文件会让传输失败。
- Windows 版只有「设备」和「设置」两个页面：键盘鼠标习惯是 Mac 上的功能。

## 在一台电脑上试用

可以在终端里运行第二台设备：

```bash
cargo run -p isthmus-link --example peer -- "Test peer"
```

它会像应用一样对外宣告自己，被请求配对时打印两台都显示的数字，并在标准输入接受 `list`、`pair <n>`、`accept`、`code <数字>`（版本 1 的设备）、`send <n> <路径>…`；已配对设备发来的剪贴板文本会被打印出来。请在「终端」或 iTerm 里运行，它们有自己的本地网络权限。

## 协议

面向贡献者；以 `crates/isthmus-link/src/wire.rs` 为准。

- 连接以 8 字节前导 `ISTHMUS\x01` 开始（它同时是 Noise prologue），接着是按长度前缀分帧的 Noise XX 握手。
- 之后每一帧都是一个大端 `u16` 长度加一条 Noise 传输消息，其明文是一个类型字节（1 为 JSON 消息，2 为文件数据）加内容。超过一帧的值（传输清单）以 `blob` 消息加数据帧发送。
- 发起方的第一条消息是带用途和协议版本的 `hello`：`session`（已配对设备之间的长连接：心跳、改名、取消配对、剪贴板）、`pair` 或 `transfer`。应答方回复带自己版本的 `welcome`，或 `refused`。
- 两台版本 2 设备之间的配对：`pairCommit`（应答方随机数的 SHA-256）、`pairNonce`（发起方的随机数）、`pairReveal`（应答方的随机数）；两边显示数字；应答方接受即 `pairResult` true，发起方以 `pairResult` true 确认。发起方为版本 1 时：`pairCodeShown`、双向 `pairSpake`、双向 `pairConfirm`、`pairResult`。
- 剪贴板，在与版本 2 设备的会话上：`clipboard` 加以 blob 发送的文本（`{"text": …}`）；版本 1 的设备不会收到。
- 一次传输：`offer`（id、数量）加以 blob 发送的条目；`accept` 加以 blob 发送的每个条目已有字节数；然后每个文件一条 `fileStart` 加从该偏移开始的数据；`done`；`finished`。任一方都可以 `cancel`。
- 更新版本的消息和枚举值会被读成 `unknown` 或不改变任何东西的值，因此两个版本之间仍能互通。
