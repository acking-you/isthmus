# Changelog

All notable changes to this project will be documented in this file.

## [Unreleased]

## [0.1.3] - 2026-11-23
- On Windows the app no longer freezes after it went to the notification area. A clipboard copy crossing while the window was hidden posted a notification through local_notifier, which called Flutter from Windows' notification threads when the notification went away, and the app stopped answering for good. Notifications now come from Isthmus's own notification-area icon, posted on the right thread, and CI runs the Windows app through the tray with a notification in between.
- On Windows the notification-area menu closes when you click elsewhere.

## [0.1.2] - 2026-11-22
- Pairing is one click on the other computer: both show the same six digits and the other computer's user clicks Accept, with nothing to type. The digits come from the encrypted connection and from random values each side commits to before seeing the other's, so a machine in the middle cannot make them match; comparing them before accepting is what catches one. A computer still on 0.1 pairs by code as before.
- The clipboard is shared with paired devices: copy text on one computer, paste it on the other, both ways, with a notice each time (a toast with the window in front, a system notification otherwise). A switch on the Devices page turns it off; what a password manager copies stays put. On a Mac that asks before apps read the clipboard (macOS 15.4 and later), the Devices page says how to allow it.
- A transfer whose path dies resumes within seconds instead of waiting minutes for TCP to give up: a write that moves nothing for 10 seconds ends the attempt, the other paths are tried first, retries start after a quarter second and keep going for 2 minutes after bytes last moved, and the receiver waits for the sender meanwhile. A retrying transfer says which retry it is, what went wrong on which path and interface, and the system's own words, and its bar keeps the real progress.
- On Windows the window has its own title bar in the app's surface, with Windows' minimize, maximize and close buttons, and Chinese text uses a bundled Noto Sans SC, whose medium and semibold weights Microsoft YaHei lacks, behind Segoe UI.

## [0.1.1] - 2026-11-22
- On Windows, file sharing starts and keep-awake can be switched on. In 0.1.0 every state file failed to save there just after it was written (the folder was opened as a file to flush it, which Windows refuses), so file sharing stopped at its first file and said "could not save the file sharing state".
- A file that cannot be read or written now says which file and why, down to the system's own words, wherever the app shows the failure.

## [0.1.0] - 2026-11-22
- Keeping the computer awake with the screen off: one switch, in Settings and in the menu bar or the notification area, stops the computer sleeping on its own while the display still turns off on its schedule, so downloads, builds, remote sessions and file sharing keep running. It is the system's own idle-sleep request (`caffeinate -i` on a Mac, a power request on Windows), named so `pmset -g assertions` and `powercfg /requests` say who holds it, released when Isthmus quits, and remembered in `awake.json`.
- Isthmus updates itself. Settings › About checks GitHub for a newer release, and the app checks on its own about twice a day unless that is switched off, announcing each new version once. Update downloads the file for this computer, checks it against the release's manifest, whose Ed25519 signature the app verifies with the key it carries, and installs it: the Windows installer updates in place and reopens the app; a Mac copies the new app out of the disk image, checks it is signed by the same developer, and swaps it in after quitting, so Accessibility stays granted; a portable copy gets the file in Downloads. The next launch says whether the update went in.
- A Windows installer, `Isthmus-windows-x86_64-setup.exe`, beside the portable zip: a Start menu shortcut and an optional desktop one, for this user or, with an administrator's permission, for everyone, removed from Settings › Apps.
- Isthmus has its own icon, the isthmus glyph (two shores joined by a narrow neck) on the blue tile, in the Dock, Finder, the Windows taskbar and the Windows notification area, in place of Flutter's.
- Holding the middle button and moving the mouse scrolls toward the pointer, faster the further it is, as Windows autoscroll does; a middle click without moving still clicks, so links still open in new tabs. It is on with the Windows preset, has a switch on the Mouse page, and leaves virtual machines and apps that drag with the middle button (Blender, Figma, CAD apps and others) alone.
- Tapping Shift alone switches between the input method and ABC, as Shift switches Chinese and English in a Windows IME (macOS's own way is Caps Lock). It is on by default, has its own switch on the Keyboard page's input source card, follows the Windows and Mac presets, and is used only when an input method such as Pinyin or WeType is installed; a key, click or other modifier in between cancels it.
- File sharing between computers. Isthmus finds other computers running it on the local network (mDNS), pairs with each once using a six-digit code shown on the other computer (SPAKE2 over a Noise-encrypted connection, keys pinned), reconnects to paired devices by itself, and sends the files and folders dropped on its window with one click on the new Devices page. Received files land in Downloads, under a free name.
- A cable straight between two computers (a USB Ethernet adapter on a KVM's hub cabled to the other computer, say) is used before the shared network: connections try it first, a session on the network moves to it when it answers, and a transfer whose path drops carries on over the next one from where it stopped.
- A Windows build of the app, for file sharing with a PC: the Devices and Settings pages, in the notification area.
- Keyboards with a Mac/Windows mode switch (Keychron and other keyboards using Apple's vendor id, and brands known for the switch) show their mode instead of a layout guess. Isthmus finds the mode with one key press (the key beside the space bar), and the menu bar has a "Windows mode" checkbox per such keyboard for after the switch is flipped, since the switch tells macOS nothing.
- Granting Accessibility is a drag and a switch: Grant opens System Settings at the Accessibility pane and puts a card under its window holding Isthmus's icon to drag into the list, so nobody has to find the app behind "+". The system's own prompt is no longer raised.
- Granting Accessibility takes effect at once: Isthmus notices the grant within a second (tccd's change notification, and a faster poll while it waits) and installs the event tap without a restart. When macOS still refuses the tap with the grant in place, the app restarts itself once instead of asking the user to.
- Isthmus makes a Mac's keyboard and mouse behave the way Windows taught your hands, from a menu-bar app that needs macOS 13 or later. A new install starts switched off and changes nothing until it is switched on; switching it off puts everything back.
- Each Windows-style keyboard gets a HID key mapping on its own services: Ctrl acts as Command, and Win and Alt sit where Windows puts them. The mapping reaches every app, password fields included. Whether a keyboard has a PC or a Mac modifier row is detected and can be corrected, and a keyboard left in Mac style is not touched. Keyboards that send media keys on F1–F12 get standard function keys in Windows style.
- An event tap translates the Windows shortcuts one key cannot express: Home and End by line, Ctrl+arrows and Ctrl+Backspace by word, Ctrl+Home and Ctrl+End, Alt+Tab with the switcher held open while Alt is held, Alt+F4, Win+D, Win+E, Win+L, Win+Tab, Win+arrows (macOS 15 tiling), Win tapped alone for Spotlight, Ctrl+Shift+Esc, Ctrl+Alt+Delete, PrintScreen and Win+Shift+S, and fixes for browsers, VS Code, Office and Finder. Ctrl+Q, Ctrl+H, Ctrl+M and Ctrl+Tab are kept from becoming Quit, Hide, Minimize and the app switcher. The shortcuts come in eight groups that switch separately, and need Accessibility.
- The app in front decides how Ctrl behaves. Terminals keep Ctrl as Ctrl and copy and paste with Ctrl+Shift+C/V; JetBrains IDEs, Emacs and Vim keep Ctrl; virtual machines and remote desktops get every key by position with nothing translated. The user's own rules, by bundle id or prefix, win over the built-in lists.
- Each wheel mouse gets Windows wheel habits: rolling toward you scrolls down, each notch scrolls three lines (one to twelve) without acceleration, buttons 4 and 5 go back and forward, and Ctrl+wheel zooms. Trackpads and the Magic Mouse keep natural scrolling.
- Each mouse gets Windows pointer speed, Windows' 1–20 scale with "Enhance pointer precision" off, as linear tracking on macOS 14 and later; on macOS 13 acceleration is switched off instead. The gain is divided by the main display's panel pixels per point, so a mouse shared through a KVM crosses the same share of the same monitor as it does on Windows.
- The keyboard and the mouse each have their own switch, each keyboard and each mouse its own settings, and the Windows and Mac presets apply to both or either in one click. Device settings follow a device across replugs, KVM switches and restarts.
- The settings live in one file, `settings.json`, that every later version reads. A key a newer version wrote, at the top level, in the keyboard or mouse section, in a device entry or in an app rule, is kept when this version rewrites the file.
- Every HID property Isthmus writes is journalled before it is written, and put back on quit, on pause, on switching to another user and, after a crash, at the next start, never over a value someone else set meanwhile. A KVM switch or a replug gets the settings again as soon as the device reappears.
- One Isthmus changes a Mac at a time: a second copy, such as another build or `isthmus run`, runs but changes nothing.
- The `isthmus` command lists devices (`devices`), shows the status and the settings (`status`, `settings`), applies a preset (`preset windows` or `preset mac`), runs without the app (`run`), puts back what a crashed run left (`restore`) and prints what devices send (`inspect`).
